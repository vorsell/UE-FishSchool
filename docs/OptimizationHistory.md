# 优化过程

项目目标是在 UE 中实现十万量级实时鱼群。优化围绕对象管理、邻域查询、并行更新和渲染提交逐步展开。

## 演进过程

| 遇到的问题 | 采用的方法 | 实现与取舍 |
| --- | --- | --- |
| 逐鱼 Actor 与骨骼动画带来较高管理成本 | 将鱼集中存入数组，采用 ISM 和资源侧 VAT | 从逐对象更新转为批处理；早期 Actor 原型不在当前源码中 |
| 全局近邻查询随数量快速增长 | 均匀网格与固定 27 格局部 KNN | 缩小候选范围；局部邻域与密集分布决定查询成本 |
| 每帧重复搜索近邻 | 按鱼 ID 分组轮换刷新邻居缓存 | 减少查询次数，以邻居信息的短暂滞后换取计算预算 |
| 串行更新与网格共享写入难以扩展 | 按属性组织数据、双缓冲和 ParallelFor；Count/Prefix/Scatter 建网格 | 明确读写缓冲及任务独占区间，代价是额外缓冲和多阶段遍历 |
| 大量遮挡区域仍执行完整行为 | CPU 粗可见性、距离档位及高低精度行为 | 关键区域保留 KNN，其余使用简化环绕；在精度和计算量之间取舍 |
| 单大 ISM 每帧全量提交 | 空间 Chunk ISM 与分级提交 | Visible 每帧、LowRender 低频、Hidden 清理旧槽；增加组件管理成本 |

当前代码保留单 ISM 和 Chunk ISM 两条路径。相关入口为 UpdateGrid、GridFindKNearestNeighbour、TraversalGridFishGroup 和 RenderChunkedInstances，具体流程见 [Architecture.md](Architecture.md)。

## 历史性能记录

开发阶段在 **RTX 2060、i7-10875H、100000 条鱼**的高压场景中，记录到约 **23 FPS → 33 FPS**。

该数据反映当时完整场景的整体优化结果，包含行为精度、可见性和渲染提交策略调整；实际表现随视角、鱼群密度和资源配置变化。各项策略的工程取舍同样是优化过程的一部分。

## 下一步

低精度行为降频、基于激活格的 Chunk 列表和逐鱼 VAT 数据仍是后续工作。GPU 仿真与 Mass/ECS 属于可评估的架构方向，当前代码保持 CPU 仿真路线。
