# 优化过程

| 早期瓶颈 | 措施 | 取舍 |
| --- | --- | --- |
| 逐鱼 Actor 与骨骼动画的管理成本 | 用数组管理鱼的状态，以 ISM 批量提交，资源侧使用 VAT | 单鱼行为统一由 Manager 调度，动画依赖材质和网格 |
| 大范围邻居查询成本 | 用均匀网格缩小到相邻 27 格，按鱼 ID 分组轮换刷新邻居缓存 | 密集格内仍要扫描候选，缓存的邻居关系可能滞后 |
| 网格和行为更新的并行写入 | SoA 与双缓冲，配合任务私有计数、前缀和与 Scatter | 多阶段遍历需要额外的计数与状态缓冲，换来明确的任务写入区间 |
| 遮挡区域的完整行为开销 | CPU 粗可见性和距离档位，使用 KNN 或简化环绕 | 以格为粒度近似遮挡，行为精度和可见鱼数会随档位变化 |
| 单 ISM 每帧全量提交 | 使用空间 Chunk ISM，按可见状态分级提交 | 更多组件与槽位管理，低频块在提交间隔内保持上次提交的变换 |

## 历史测试

早期完整场景在 **RTX 2060、i7-10875H、100000 条鱼**的高压场景中记录到约 **23 FPS → 33 FPS**。这是多项改动共同作用下的整场景记录，包含粗可见性带来的显示数量变化。
